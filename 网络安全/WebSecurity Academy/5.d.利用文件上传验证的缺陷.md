## 在实际应用中，你很难找到像我们之前实验看到的那样，完全没有文件上传攻击保护的网站。但仅仅因为有防御措施，并不意味着它们就很坚固。你有时仍然可以利用这些机制的漏洞，获得用于远程代码执行的Web shell。

# 有缺陷的文件类型验证

## 提交 HTML 表单时，浏览器通常通过 `POST` 请求发送提供的数据，内容类型为 `application/x-www-form-urlencoded`。发送简单短信如姓名或地址时，这没问题。然而，它不适合发送大量二进制数据，比如完整的图像文件或 PDF 文档。在这种情况下，优先选择内容类型 multipart/form-data


## 考虑一个包含上传图片、提供图片描述和用户名输入字段的表单。提交此类表格可能会收到类似这样的请求：
```
POST /images HTTP/1.1 
	Host: normal-website.com 
	Content-Length: 12345 
	Content-Type: multipart/form-data; boundary=---------------------------012345678901234567890123456 
	---------------------------012345678901234567890123456 
	Content-Disposition: form-data; name="image"; filename="example.jpg" 
	Content-Type: image/jpeg 
	[...binary content of example.jpg...] 
	---------------------------012345678901234567890123456 
	Content-Disposition: form-data; name="description" 
	This is an interesting description of my image. 
	---------------------------012345678901234567890123456 
	Content-Disposition: form-data; name="username" 
	wiener 
	---------------------------012345678901234567890123456--

```


## 如你所见，消息正文根据表单的每个输入被拆分成不同的部分。每个部分都包含一个`Content-Disposition`头部，提供关于其相关输入字段的一些基本信息。这些独立部分还可以包含自己的 `Content-Type` 头部，告诉服务器使用该输入提交的数据的 MIME 类型。


## 网站验证文件上传的一种方法是检查该输入特定的`内容类型`头是否匹配预期的 MIME 类型。如果服务器只期望图片文件，比如，它可能只允许像 `image/jpeg` 和 `image/png` 这样的类型。当服务器隐式信任该头部值时，可能会出现问题。如果没有进一步验证文件内容是否与所谓的 MIME 类型匹配，这种防御可以用 Burp Repeater 等工具轻松绕过。
