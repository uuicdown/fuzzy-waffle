## 在某些情况下，敏感功能会通过赋予更难预测的网址来隐藏。这就是所谓“隐蔽性安全”的一个例子。然而，隐藏敏感功能并不能提供有效的访问控制，因为用户可能会通过多种方式发现被混淆的 URL。

## 想象一个托管管理功能的应用程序，URL 如下：

```
https://insecure-website.com/administrator-panel-yb556
```

## 攻击者可能无法直接猜测。然而，应用仍可能向用户泄露该 URL。URL 可能在 JavaScript 中披露，JavaScript 根据用户角色构建用户界面：
```script
<script> 
	var isAdmin = false; 
	if (isAdmin) {
	 ... 
	 var adminPanelTag = document.createElement('a');
	 adminPanelTag.setAttribute('href', 'https://insecuwebsite.com/administrator-panel-yb556');
	  adminPanelTag.innerText = 'Admin panel'; 
	  ... }
</script>
```

## 如果用户是管理员用户，这个脚本会添加指向用户界面的链接。然而，包含该 URL 的脚本对所有用户均可见，无论其角色如何。
