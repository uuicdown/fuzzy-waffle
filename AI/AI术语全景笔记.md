## 底层逻辑总纲

**一句话穿透所有术语：**  
AI领域的每一个术语，本质上都是一个**"痛点解决器"**——某个科学家遇到了一个具体问题，发明了一个词/一种技术把它解决了。

**终极主线（3句话串起全文）：**

> 1. **LLM本质上是"下一个token概率预测器"**，不是计算器，不是思考者。它没有思维，只有统计分布。
> 2. **所有术语都可以归类到这条流水线上：**
>    `Embedding（编码入口）→ Latent Space（战场）→ Attention（探照灯）→ 预测输出`
> 3. **所有实战技术（RAG / Fine-tune / RLHF）都只做一件事：** 修正这条流水线上某个环节的"数据或行为"，让它更适合你的场景。没有哪个技术是"魔法"。

## 核心术语详解 · 七层塔

### 🔷 第一层：Embedding（嵌入）—— 把"意思"装进数字

| 维度 | 内容 |
|---|---|
| **是什么** | 每个词 → 一个由几百个数字组成的坐标向量 |
| **核心特性** | 语义相近的词，坐标距离近；语义无关的词，坐标距离远 |
| **降维映射** | RGB颜色编码。 (255,0,0)=纯红，(255,50,50)=偏粉红——"距离"反映"相似度" |
| **经典类比推理** | 「国王」-「男人」+「女人」≈「女王」。这是embedding空间的**固有几何性质**，不需要任何额外模块参与。 |
| **你要记住** | Embedding ≠ Attention。Embedding负责把词投影到空间；Attention负责在这个空间里动态聚焦。职责分离。 |

**认知盲区（我们打通过的）：**
- ❌ 以为"国王-男人+女人=女王"是Attention做的 → ✅ 纯属Embedding空间的向量几何
- ❌ 以为Embedding只是一个字典查表 → ✅ 它是整个AI推理发生的"坐标系"，承载一切后续操作

---

### 🔷 第二层：Attention（注意力机制）—— "我该看哪"

| 维度 | 内容 |
|---|---|
| **是什么** | 对输入序列中的每个词，动态计算它跟其他所有词之间的"相关性分数" |
| **核心特性** | 无视距离。相隔15个词的"他"和"约翰"一样能被关联起来 |
| **降维映射** | 在地铁车厢里找朋友——不从头走到尾逐个排查，而是瞬间对所有面孔做一次相似度对比，高相似度者被"聚焦" |
| **要澄清的"权重"** | Attention的"权重" ≠ 算数加减法用的权重。它是"这个位置的值在最终输出中应该被放大/缩小的倍数"。 |

**认知盲区（我们打通过的）：**
- ❌ "Attention给国王减男人加女人" → ✅ Attention是判断相关性的工具，不是做向量运算的工具
- ❌ Attention权重是固定的 → 权重完全**动态**，同一句子换一种问法，权重全部重算

---

### 🔷 第三层：Latent Space（潜空间）—— AI的"后台"

| 维度 | 内容 |
|---|---|
| **是什么** | AI进行所有内部推理的"战场"——一个高维（几百到几千维）的数学空间 |
| **降维映射** | 柏拉图的洞穴寓言。你看到墙上的影子（输入文字），但AI的工作发生在墙后面的"真实世界"（潜空间） |
| **为什么叫"潜"** | 人脑无法直接理解这个空间中的一个点所代表的东西。它摊平了一个概念的所有特征维度，是"AI的潜意识" |
| **参数与空间大小的关系** | 100亿参数 = 10m²毛坯房；1000亿参数 = 三层别墅。空间大了，才能同时处理多个复杂的关联推理 |

**完整推理流水线：**
> 输入文字 → **Embedding**（投影成坐标点，进入Latent Space） → **Attention**（在Latent Space中反复重组、关联、聚焦） → 反向解码成输出文字

---

### 🔷 第四层：Temperature（温度）—— AI的"疯癫旋钮"

| 维度 | 内容 |
|---|---|
| **是什么** | 控制模型输出随机性的参数 |
| **降维映射** | 喝了几杯酒。清醒=低Temperature，喝醉=高Temperature |
| **工作原理** | 模型对每个候选token给一个概率分布 → Temperature低：概率分布被拉尖，最高概率选项几乎100%被选 → Temperature高：概率分布被抹平，小概率选项被激活 |
| **实战值** | 代码/算术/事实问答：0～0.3 | 日常对话：0.5～0.7 | 创作/头脑风暴：0.8～1.2 |
| **一句话暴击** | Temperature不是"创造力开关"。低Temperature不是"没创造力"，是"追求一致性"；高Temperature不是"变聪明"，是"增加随机性"。 |

---

### 🔷 第五层：RAG vs Fine-tuning —— 开卷 vs 闭卷

| 维度 | RAG（检索增强生成） | Fine-tuning（微调） |
|---|---|---|
| **类比** | 开卷考试。知识在外部书里。 | 闭卷考试。知识记在脑子里。 |
| **模型改不改** | 不改 | 改参数（权重被微调） |
| **知识在哪** | 外部向量数据库 | 模型内部参数 |
| **修改知识** | 改数据库文档就行 | 重新训一遍 |
| **成本** | 低（检索+推理） | 高（训练算力） |
| **深度推理** | 一般（只看到检索回来的片段） | 强（学到完整模式） |
| **适用场景** | 事实查询、多变的个人化数据（病历） | 行为迁移、风格固化、能力增强 |

**行业铁律：能RAG就别Fine-tune。** 用外部知识解决问题，不动模型参数。

**最佳组合拳：** RAG打头阵快速上线 → 观察高频需求模式 → 用Fine-tune固化。

---

### 🔷 第六层：RLHF（人类反馈强化学习）—— "说好话"不是天生的

| 维度 | 内容 |
|---|---|
| **是什么** | 用人类对模型输出的打分数据，训练一个Reward Model（评分模型），再用它调整GPT的行为倾向 |
| **降维映射** | 训狗。狗不知道"坐"是对的还是好的——它只知道"坐"了之后能拿到肉。 |
| **它改变了什么** | 没有改变模型"知道什么"，只改变了模型"选择说什么"的概率分布 |
| **它没改变什么** | 模型依然"知道"怎么写种族歧视的内容（参数没被擦除），但输出那条路被RLHF压到了极低的概率 |
| **一句话暴击** | RLHF不是在教AI"对错"，而是在教AI"怎么让人类点赞"。AI的道德感，本质上是人类打分数据的统计学投影。 |

---

### 🔷 第七层：参数规模 —— 多出来的参数到底"多"在哪

| 100亿参数 | 1000亿参数 |
|---|---|
| 小城市图书馆（畅销书+教科书） | 国会图书馆（古籍+手稿+冷门语种+全部论文） |
| 能处理高频、常见的语言模式 | 能处理稀疏、长尾、高度抽象的关联 |
| 覆盖日常对话、常识问答 | 覆盖专业领域、跨学科类比、极端小众知识 |
| Latent Space = 毛坯房 | Latent Space = 三层别墅 |

**核心结论：** 参数不是"重复抄写"，而是"填补空间中更稀疏、更细分、更长尾的部分"。模型不是变努力了，是能看到更细微的关联了。

## 查尔摩斯通用分析框架（未来可套用在任何AI问题上）

面对一个AI相关的决策/问题时，按以下4个维度拆解：

### Step 1：定位阶段
```
是"训练时问题"还是"推理时问题"？
  ↗ Training: Fine-tuning / RLHF / 预训练
  ↘ Inference: Prompt Engineering / RAG / Temperature
```

### Step 2：选型逻辑树
```
你想干什么？
  ① 给模型新信息？   → RAG（不改模型） / Fine-tune（改模型）
  ② 改变模型行为？   → RLHF（打分训） / System Prompt（规则写死）
  ③ 调整输出风格？   → Temperature（旋钮）
  ④ 提升深度能力？   → 换更大参数模型 / Fine-tune
```

### Step 3：风险排查
```
- 模型会编造事实吗？                              → 上RAG + 低Temperature
- 模型会输出有害内容吗？                          → RLHF
- 模型回答不稳定（同一个问题给不同答案）？         → 降低Temperature
- 模型对长尾知识回答不精准？                       → RAG（短平快）→ Fine-tune（长期固化）
```

### Step 4：组合策略（实战兜底公式）
> **RAG先上线 → 发现模式 → Fine-tune固化 → RLHF对齐 → 调Temperature微调输出**
