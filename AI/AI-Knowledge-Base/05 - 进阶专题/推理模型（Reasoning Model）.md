# 推理模型（Reasoning Model / o1 / R1）

> ✅ 已学习 — 2026-05-18
>
> 在推理时生成内部思维链，花更多时间"思考"后再给出答案的模型。
> 代表：OpenAI o1 / o3、DeepSeek-R1。

---

## 一句话本质

**传统 LLM（GPT-4、Claude）用计算资源换生成质量——推理模型（o1、R1）用时间换思考深度。**

---

## 传统 LLM vs 推理模型

```
传统 LLM（GPT-4）：
  用户提问 → 模型立即开始生成回答 → 一次过 → 输出
  特点：快（几秒），适合简单问答

推理模型（o1 / R1）：
  用户提问 → 模型在内部生成"思考链"（不可见） 
            → 自我验证 → 修正 → 再思考
            → 最终输出
  特点：慢（几十秒到几分钟），适合复杂推理
```

---

## 关键机制：Test-time Compute

```
传统 LLM 把资源花在训练时（Pre-training 烧几千万美元）
推理时很省（一次前向传播）

推理模型反过来了：
  训练时和传统 LLM 差不多
  推理时花更多计算资源（内部反复搜索、验证、修正）

这叫 Test-time Compute Scaling——推理时计算量越大，答案质量越高。
```

---

## 什么场景用推理模型

| 场景 | 传统 LLM | 推理模型 |
|---|---|---|
| 日常对话 | ✅ 快，够用 | ❌ 太慢，没必要 |
| 翻译 | ✅ 够用 | ❌ 杀鸡用牛刀 |
| 代码生成 | ⚠️ 简单代码够 | ✅ 复杂算法推理 |
| 数学证明 | ❌ 容易错 | ✅ 强项 |
| 逻辑推理 | ⚠️ 一般 | ✅ 强项 |
| 科学分析 | ❌ 不够深 | ✅ 适合 |

---

## 省流总结

```
简单任务 → 传统 LLM（快、便宜）
复杂推理 → 推理模型（慢、贵、但准确）
实用策略：先给传统 LLM，答不上来再交给推理模型
```
