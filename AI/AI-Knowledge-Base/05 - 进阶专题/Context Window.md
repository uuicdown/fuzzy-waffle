# 上下文窗口（Context Window）

> ✅ 已学习 — 2026-05-18
>
> 模型一次能"看到"的最大 token 数。窗口越大，能处理的内容越多。

---

## 一句话本质

**Context Window = 模型每次推理时能同时看到的上下文的长度上限。**

```
超出窗口的内容 → 模型看不到 → 等于不存在
```

---

## 主流模型的窗口大小

| 模型 | 窗口大小 | 备注 |
|---|---|---|
| GPT-4 / GPT-4o | 128K | |
| Claude 3 / 4 | 200K | |
| Gemini 1.5 Pro | 1M | 当前最大 |
| DeepSeek-V2/V3 | 128K | |
| Llama 3 | 8K | 小窗口，但扩展性好 |

---

## 窗口不够用时怎么办

### 方案一：截断（最粗暴）

```
对话超过 128K token →
  只保留最近 N 轮（丢弃最早的）
  模型不知道被截掉的内容
```

### 方案二：滑动窗口

```
不是等到攒满 128K 再截断
每轮对话把最早的 1 轮丢弃 → 始终保持窗口内有最新的 N 轮
Mistral 用这个方案
```

### 方案三：RAG（最实用）

```
窗口不够存全部知识 → 不存了
把知识放向量数据库 → 需要时检索相关片段塞进窗口
→ 窗口只要装得下"当前需要的内容"就行
```

### 方案四：RoPE 扩展

```
训练时窗口 = 4K
但 RoPE 天然支持外推 → 推理时窗口可以扩展到 32K / 128K
效果随扩展倍数增大而下降，但聊胜于无
```

---

## 窗口大小的 tradeoff

| 窗口大 | 窗口小 |
|---|---|
| 能处理长文档 | 长文档必须截断 |
| 对话记忆更长 | 对话容易"失忆" |
| Attention O(n²) 计算慢 | 计算快 |
| KV Cache 占显存多 | 显存省 |
| 幻觉更容易（长输入干扰多） | 幻觉少 |

---

## 实用建议

```
长文档分析 → 优先用 Claud 200K 或 Gemini 1M
日常对话 → 128K 足够（GPT-4 / DeepSeek）
代码仓库 → 需要 128K+ 全文件分析
RAG 场景 → 不需要大窗口（窗口只装检索结果）
```
