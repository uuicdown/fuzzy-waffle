# 推理优化与部署

#进阶专题 #推理 #部署 #kv-cache #flash-attention

## 一句话
LLM 推理的瓶颈是**自回归串行性 + 显存墙**。优化手段从减少重复计算（KV Cache）到突破显存带宽（FlashAttention）、再到操作系统级内存管理（PagedAttention）和投机取巧（Speculative Decoding），形成完整的加速栈。

## 降维映射：「出版社出书」
| 技术 | 类比 |
|------|------|
| KV Cache | 编辑审稿不留笔记，每次重读全书？不——之前批注（KV）留在便签上 |
| FlashAttention | 不把整本书摊桌上，一次只看一页，书桌保持整洁 |
| PagedAttention | 图书馆灵活排架——书可放在任意空位，不需预留固定空间 |
| Continuous Batching | 扶梯而非电梯——随时上下，不等整批 |
| Speculative Decoding | 实习编辑快速草稿，主编一次性审核 |
| 量化 | 精装硬皮书→口袋简装版 |

## 核心机制

### KV Cache：推理优化的第一性原理
Attention 中每个 Token 都生成 K、V 向量。生成 Token n 需要 Token 1~n-1 的所有 K、V。不缓存 = 每步重算全部 O(n²)。缓存 = **空间换时间**，O(n²) → O(n)。

**代价**：70B 模型、1000 Token 的单请求 KV Cache 占 ~2.6GB。100 并发 = 260GB——比模型权重还大。

### PagedAttention（vLLM 核心创新）
灵感来自 OS 虚拟内存分页。KV Cache 被分成固定 Block，按需分配、不连续存放、可跨请求共享（如相同 System Prompt）。显存利用率 +24%，吞吐 2-4x。

### FlashAttention：连内存都不让看全
核心洞见：标准 Attention 的瓶颈不是计算，是 HBM↔SRAM 之间的数据搬运。解法：分块（Tiling）+ Online Softmax + 不写回中间矩阵（Recomputation）。2-4x 加速，O(N²)→O(N) 显存。

### Speculative Decoding：无损加速 2-3x
小模型（Draft，如 0.5B）快速生成 K 个候选 Token → 大模型（Target）一次验证全部 K 个 → 数学上等价于大模型自回归，不损失质量。SSD（Saguaro, ICLR 2026）：草稿模型预判验证结果，再快 30%。

### 注意力架构减重
- **MQA**：所有头共享 K、V → KV Cache 缩为 1/头数
- **GQA**：Q 头分组，每组共享 K、V → 折中方案（LLaMA 系列）
- **MLA**：K、V 压缩到低维 Latent 空间存储 → 极致压缩（DeepSeek-V2/V3）

## 🧪 摸底自测

#### Q1（入门）
> KV Cache 解决什么问题？没有它的话生成第 100 个 token 时会发生什么？

<details>
<summary>解答</summary>

生成第 N 个 token 时，需要前面 N-1 个 token 的 K 和 V。没有 KV Cache 就要重新算全部 N-1 个的 K/V → O(n²) 重复计算。KV Cache 把每步算好的 K/V 存起来 → O(n)。代价：用显存换速度。
</details>

#### Q2（进阶）
> FlashAttention 加速的核心瓶颈是什么？它用 tiling 解决了什么问题？

<details>
<summary>解答</summary>

瓶颈不是计算，是 HBM←→SRAM 之间的数据搬运（标准 Attention 90% 时间花在搬数据）。FlashAttention 把 Q/K/V 切成小块加载到 SRAM，在 SRAM 里一口气算完，只把最终结果写回 HBM。HBM 读写从 O(N²) 降到 O(N)。
</details>

#### Q3（提升）
> GQA 和 MHA、MQA 的区别是什么？DeepSeek 的 MLA 更进一步做了什么？

<details>
<summary>解答</summary>

MHA：每个 Query 头有独立的 K/V → KV Cache 占 32 份。MQA：所有 Query 头共享 K/V → 省但质量下降。GQA：Query 分组，每组共享 K/V → 折中（Llama 3、GPT-4 使用）。MLA：把 K/V 压缩到低维 latent space 存储 → KV Cache 只有 MHA 的 5-10%（DeepSeek-V2/V3 的核心优势）。
</details>
