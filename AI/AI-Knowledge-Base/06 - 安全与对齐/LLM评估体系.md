# LLM 评估体系

#安全与对齐 #评估 #ragas

## 一句话
LLM 评估的核心矛盾：输出是「开放域自然语言」，工程需要「可量化的数字」。**像批改作文，不是批改选择题。**

## 三代演进

### 第一代：词汇匹配（BLEU/ROUGE/METEOR）
数 n-gram 重叠率。「好翻译 = 和参考译文用词一致」。致命缺陷：用词数来评作文，同义词也扣分。LLM 时代全面失效。

### 第二代：LLM-as-Judge（2023-至今）
让一个 LLM 评判另一个 LLM 的输出。三种路径：

| 方法 | 做法 | 类比 |
|------|------|------|
| 打分法（G-Eval） | 按评分标准打 1-5 分 | 作文阅卷老师 |
| 对比法（Arena ELO） | 用户盲选 A/B，累积 ELO | 国际象棋排名 |
| 分解法（RAGAS Faithfulness） | 拆成原子声明，逐条验证 | 法医解剖 |

**LLM-as-Judge 的四大偏见**：
- 位置偏见：倾向认为后面的答案更好
- 长度偏见：倾向给更长的回答高分
- 自我偏好：同模型倾向给自己高分
- 风格偏见：正式文字容易得高分

### 第三代：生产可观测性
离线评估和在线监控统一为循环：离线评估 → 在线监控 → 数据回流 → 迭代优化。

四层指标：L1 系统（延迟/吞吐）→ L2 检索（召回/精确）→ L3 生成（忠实度/相关性）→ L4 业务（满意度/采纳率）

## RAGAS：RAG 评估事实标准
2×2 矩阵：检索（精确×召回）× 生成（忠实度×相关性）

| 指标 | 衡量什么 | 降维映射 |
|------|---------|---------|
| Faithfulness（忠实度） | 回答有没有加戏？ | 法庭证人宣誓——只陈述所见 |
| Answer Relevancy（答案相关性） | 有没有答非所问？ | 问地铁站→答地铁历史（跑题） |
| Context Recall（上下文召回） | 检索有没有漏？ | 5 个要点只覆盖了 3 个 |
| Context Precision（上下文精确） | 有用的排前面了吗？ | 真正相关在第 4、5 位→Lost-in-Middle |

**综合分 = 调和平均数**：对低分极其敏感——木桶的短板决定全局。

## 基准测试困境
- **饱和**：MMLU 所有人考 98-100 分，失去区分度
- **污染**：训练数据见过原题 → 可能是「背答案」而非「会了」
- **应对**：动态基准（Chatbot Arena）、私有基准、能力探针

## 常见反模式
1. 只看综合分不分解 → 召回 0.3 的烂系统可能综合分尚可
2. 只跑一次评估 → 评估应是 CI/CD 流水线
3. 用弱模型评强模型 → 评估下限决定可信度
4. 没有基线对比 → 绝对值不重要，变化量重要
