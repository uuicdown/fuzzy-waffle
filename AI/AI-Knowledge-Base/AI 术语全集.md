## 01 - 核心机制（全部已学 ✅）

### 大语言模型（LLM, Large Language Model）
- **是什么**：基于 Transformer 架构、在海量文本上预训练的语言模型，参数量通常在数十亿以上。
- **解决什么问题**：让机器能理解和生成人类语言，作为所有 AI 对话产品的基础。
- ✅ **已学**

### Tokenization（分词）
- **是什么**：把文本切碎成模型能处理的基本单位（token）的过程。英文常用 BPE 算法，一个 token 约 0.75 个词。
- **解决什么问题**：把连续文本转换成离散的 token ID 序列，让模型能处理文字。核心矛盾是"用最少的 token 数表达最多的语义"。
- ✅ **已学**

### Embedding（嵌入）
- **是什么**：把离散的 token 映射到连续的低维向量空间，语义相近的词在空间中距离近。
- **解决什么问题**：让模型能"理解"词义之间的关系——"king - man + woman ≈ queen"。
- ✅ **已学**

### Self-Attention（自注意力机制）
- **是什么**：每个 token 通过 QKV 机制计算与其他所有 token 的相关度，加权聚合信息。公式：Attention = softmax(QK^T/√d)V。
- **解决什么问题**：让模型在处理某个词时，能动态地"看到"句子中其他位置的相关信息，解决长距离依赖问题。
- ✅ **已学**

### Transformer（变换器）
- **是什么**：由 Self-Attention + FFN + 残差连接 + LayerNorm 堆叠而成的架构，现代 LLM 的基础。
- **解决什么问题**：替代 RNN/LSTM，实现并行计算 + 长距离依赖捕获。
- ✅ **已学**

### Latent Space（潜空间）
- **是什么**：模型内部的高维向量空间（如 4096 维），所有推理都在这个空间中发生。
- **解决什么问题**：把现实世界的语义/知识编码成数学上可操作的向量，让模型能"在空间中移动向量"来完成推理。
- ✅ **已学**

### Autoregressive Decoding（自回归解码）
- **是什么**：模型一次只生成一个 token，每次把刚生成的 token 拼回输入，再预测下一个。所有现代 LLM 的生成方式。
- **解决什么问题**：让模型能逐步生成任意长度的文本，每一步都基于已生成的内容。
- ✅ **已学**

### FFN（前馈网络）
- **是什么**：Transformer Block 中的计算层，先升维再降维（通常 4x），对 Attention 聚合后的信息做非线性变换。
- **解决什么问题**：Attention 做"信息路由"，FFN 做"特征加工"——缺了 FFN，Attention 的输出无法被进一步抽象和计算。
- ✅ **已学**

### Residual Connection（残差连接）
- **是什么**：在层间添加一条"短路"，让信息可以直接跳过一些层。
- **解决什么问题**：解决深层网络的梯度消失问题——梯度可以从"高速公路"直接传回浅层，让 100+ 层的网络能训练起来。
- ✅ **已学**

### Layer Normalization（层归一化）
- **是什么**：对每个样本的所有维度做归一化（不依赖 batch 统计量）。
- **解决什么问题**：稳定训练过程，加速收敛。Transformer 用 LayerNorm 而非 BatchNorm，因为序列长度不固定。
- ✅ **已学**

### Softmax
- **是什么**：把 logits（任意实数）转成概率分布（和为 1，每个值在 0-1 之间）。公式：P(i) = e^z_i / Σ e^z_j。
- **解决什么问题**：让模型输出可以解释为"每个 token 出现的概率"，是模型输出的最后一道门。
- ✅ **已学**

### Cross-Entropy Loss（交叉熵损失）
- **是什么**：衡量模型预测分布和真实分布的差异。LLM 中：Loss = -log(P(正确 token))。
- **解决什么问题**：提供训练信号——模型给正确答案的概率越低，Loss 越高，梯度越强，推动模型调整。
- ✅ **已学**

### Backpropagation（反向传播）
- **是什么**：从输出层往输入层反向计算每个参数对 Loss 的贡献（梯度）。核心是链式法则。
- **解决什么问题**：让深度神经网络可以训练——有了梯度，优化器才知道每个参数该往哪个方向调。
- ✅ **已学**

### Optimizer（优化器，Adam/AdamW）
- **是什么**：根据梯度更新参数的算法。Adam 加了动量（历史方向）和自适应学习率（每个参数独立步长）。
- **解决什么问题**：SGD 容易震荡或陷入局部最优，Adam 走得更稳、收敛更快。
- ✅ **已学**

## 02 - 模型训练

### Pre-training（预训练）
- **是什么**：在互联网海量文本上做 Next Token Prediction，产出"续写机器"——有语言能力和知识储备，但不会回答问题。
- **解决什么问题**：用全互联网的数据教会模型语言规律和世界知识。占整个训练 95-97% 的算力。
- ✅ **已学**

### SFT（监督微调, Supervised Fine-Tuning）
- **是什么**：用人工标注的指令-回答对（1 万-10 万条）训练模型，教会它"问答格式"。
- **解决什么问题**：把"续写机器"变成"会回答问题的机器"。解决 Pre-training 产出的模型不懂"提问→回答"这个社交规范的问题。
- ✅ **已学**

### RLHF（基于人类反馈的强化学习）
- **是什么**：人类对模型的多个回答做偏好排序，训练奖励模型，再用强化学习（PPO）让模型学会"什么样的回答更好"。
- **解决什么问题**：解决 SFT 只能教"格式"不能教"质量"的问题——让模型从"及格"变成"优秀"。
- ✅ **已学**

### Fine-tuning（微调）
- **是什么**：在预训练模型的基础上，用特定领域数据继续训练，让模型变成该领域的专才。
- **解决什么问题**：通用模型在特定领域不够精准——微调让模型适应垂直场景（法律、医疗、客服等）。
- ✅ **已学**

### LoRA（低秩适配）
- **是什么**：冻结原模型权重，插入两个小矩阵 A×B（仅几万参数），只更新这两个矩阵。
- **解决什么问题**：Full Fine-tuning 70B 需要 ~1TB 显存，LoRA 只需要 ~150GB。省了 10 倍的显存和存储。
- ✅ **已学**

### QLoRA（量化低秩适配）
- **是什么**：LoRA + 模型权重量化（FP16 → INT4），进一步压到 ~24GB 显存。
- **解决什么问题**：让 70B 模型也能在消费级显卡（RTX 4090）上微调。
- ✅ **已学**

### PEFT（参数高效微调, Parameter-Efficient Fine-Tuning）
- **是什么**：LoRA 及其变体（Adapter、Prefix Tuning、Prompt Tuning 等）的统称。
- **解决什么问题**：在不更新全部参数的前提下微调大模型，降低训练成本和存储成本。
- 🔶 **部分掌握**（已学 LoRA）

### 模型量化（Quantization）
- **是什么**：把模型权重从 FP16（2 字节/参数）压缩到 INT8 或 INT4（0.5 字节/参数），体积缩小 4-75%。
- **解决什么问题**：让大模型能在显存更小的设备上运行，或者在同一 GPU 上运行更大的模型。
- 🔶 **部分掌握**（有笔记内容）

### 数据集构建
- **是什么**：从原始数据（Common Crawl、代码、书籍等）经过清洗、去重、质量打分、配比调整等步骤，产出训练用的高质量数据集。
- **解决什么问题**：原始互联网数据 60%+ 是垃圾，需要系统化的数据工程才能训练出好模型。
- ⬜ **待学**

### 评估指标（Loss / Perplexity / Benchmark）
- **是什么**：衡量模型训练效果的各种指标。Perplexity 衡量"模型对下一个 token 的预测有多困惑"，Benchmark 是标准化测试集。
- **解决什么问题**：没有指标就无法判断模型有没有变好。
- ⬜ **待学**

### Training Pipeline（训练流水线全景）
- **是什么**：Pre-training → SFT → RLHF 的完整流程。Pre-training 做语言能力，SFT 做格式对齐，RLHF 做质量对齐。
- **解决什么问题**：三步缺一不可——单做 Pre-training 模型不会回答，单做 SFT 模型回答平庸，单做 RLHF 模型没有知识根基。
- ✅ **已学**

## 03 - 工程应用

### API 调用
- **是什么**：通过 HTTP POST 请求把 messages（系统指令 + 对话历史 + 新问题）和参数发给模型服务器，拿到生成的文本响应。
- **解决什么问题**：让开发者能通过几行代码接入大模型能力，不需要自己部署和训练。
- ✅ **已学**

### 流式输出（Streaming）
- **是什么**：模型逐 token 推送生成结果（SSE 协议），而不是等全部算完再一次性返回。
- **解决什么问题**：降低用户感知的延迟——第一个 token 算出来就能显示，实现"打字机效果"。
- ✅ **已学**

### Temperature（温度）
- **是什么**：在 Softmax 前对 logits 做缩放，控制输出概率分布的"陡峭度"。
- **解决什么问题**：控制回答的随机性/创造性——代码生成用低 T（精确），创意写作用高 T（多样）。
- ✅ **已学**

### Top-p Sampling（核采样）
- **是什么**：只从累积概率达 p 的 top token 集合中采样，排除低概率的"长尾"选项。
- **解决什么问题**：防止模型选到极低概率的离谱 token，同时保留多样性。
- ✅ **已学**

### RAG（检索增强生成）
- **是什么**：模型在回答问题前，先从外部知识库检索相关文档，把检索结果作为上下文一起交给模型生成。
- **解决什么问题**：解决模型知识滞后、幻觉、缺乏来源的问题——相当于"开卷考试"。
- ✅ **已学**

### Reranker（重排序器）
- **是什么**：在向量检索出 top-k 结果后，用更精细的模型对结果重新排序，把最相关的排前面。
- **解决什么问题**：向量检索的初筛结果不够精确——重排序器提升最终质量。
- ⬜ **待学**

### Prompt Engineering（提示词工程）
- **是什么**：设计 System Prompt 和 User Prompt 的技巧——用五要素框架（角色、任务、上下文、格式、约束）缩小模型的猜测范围，让输出更精准。
- **解决什么问题**：模型的行为高度依赖提示词——好的提示词能榨出模型最好的能力，差的提示词会让模型"乱跑"。
- ⬜ **待学**

### Chain of Thought（思维链, CoT）
- **是什么**：在提示词中要求模型"一步步思考"，把推理过程显式写出来再给出答案。最简单的用法：在问题末尾加"请一步步思考"。
- **解决什么问题**：复杂推理任务中模型直接跳到最后答案容易犯错——CoT 让每步结果可见可验证，推理准确率提升 20-50%。
- ✅ **已学**

### Function Calling（函数调用）
- **是什么**：模型不执行工具，只返回"该调用哪个工具、传什么参数"的结构化指令，由系统执行。
- **解决什么问题**：让模型从"只能输出文字"变成"可以调用外部工具"——模型做决策，系统做执行。
- ✅ **已学**

### AI Agent（AI 智能体）
- **是什么**：LLM + 工具 + 循环。模型在循环中持续思考→调用→观察→再思考，直到完成任务。
- **解决什么问题**：单次 API 调用只够做简单问答——复杂任务需要多步推理和工具调用，Agent 循环解决了这个问题。
- ✅ **已学**

### 多 Agent 架构
- **是什么**：主 Agent 做规划和调度，子 Agent 各司其职（写代码、测试、搜索等），协作完成任务。
- **解决什么问题**：单 Agent 做所有事容易选错工具、提示词过长。多 Agent 让每个 Agent 职责专一，减少出错。
- ✅ **已学**

### MCP（模型上下文协议, Model Context Protocol）
- **是什么**：Anthropic 发起的标准化协议，统一了工具的描述格式和通信方式。
- **解决什么问题**：Function Calling 各厂商实现不同——MCP 让工具的描述和调用标准化，一次开发到处运行。
- 🔶 **部分掌握**（有笔记内容）

### 向量数据库
- **是什么**：专门存储和检索向量 Embedding 的数据库（FAISS / Pinecone / Milvus / Chroma）。用 ANN 算法（HNSW）加速搜索，建多层索引后只比较几十个向量而非全部。
- **解决什么问题**：RAG 需要快速找到和用户问题最相关的文档——在百万级数据中毫秒级返回最相似的 top-k。
- ✅ **已学**

### 缓存（Cache / Prompt Caching）
- **是什么**：API 提供方对重复的输入前缀缓存推理结果，命中时直接返回。
- **解决什么问题**：节省推理时间和成本——命中时价格可低至 10-50%。
- ✅ **已学**

## 05 - 进阶专题

### Dense 模型（稠密模型）
- **是什么**：推理时所有参数全部激活的传统 Transformer 模型（GPT / Llama / Claude）。和 MoE 相对。
- **解决什么问题**：结构简单、训练稳定、推理显存需求小。但参数全激活，成本随参数线性增长。
- ✅ **已学**

### MoE（混合专家模型, Mixture of Experts）
- **是什么**：把 Transformer 的 FFN 拆成多个"专家"子网络，通过 Router 分配 token，推理时只激活其中几个专家。DeepSeek-V3 总参数 671B，每次只激活 37B。
- **解决什么问题**：在不显著增加推理成本的前提下增大模型总参数量——效果看总参数（671B 级），成本看激活参数（37B 级）。
- ✅ **已学**

### Router（路由网络 / 门控网络）
- **是什么**：MoE 中专用的分配器——给每个专家打分，选中分数最高的 top-2 专家处理当前 token。本身是一个小神经网络，和模型一起训练出来。
- **解决什么问题**：决定"这个 token 该交给哪个专家"——Router 选错了会导致专家失衡、效果下降。
- ✅ **已学**

### GQA（分组查询注意力, Grouped Query Attention）
- **是什么**：多个 Query 头分组，每组共享同一组 Key 和 Value。MHA（每个头独立 K/V）和 MQA（所有头共享 K/V）的折中。
- **解决什么问题**：减少 KV Cache 显存占用（从 MHA 的 32 份降到 8 份），同时质量损失小于 MQA。Llama 3、GPT-4 使用。
- ✅ **已学**

### MLA（多头潜注意力, Multi-head Latent Attention）
- **是什么**：DeepSeek 的 KV Cache 压缩方案——把 K 和 V 压缩到低维 latent space 存储。
- **解决什么问题**：KV Cache 只有 MHA 的 5-10%，是 DeepSeek 支持超长上下文的核心技术。
- ✅ **已学**

### Positional Encoding（位置编码）
- **是什么**：给每个 token 加上位置信号（正弦波或 RoPE），让模型知道 token 的先后顺序。
- **解决什么问题**：Self-Attention 对集合做运算，不天然区分顺序。
- ✅ **已学**

### RoPE（旋转位置编码, Rotary Position Embedding）
- **是什么**：在 Attention 计算中对 Q 和 K 做旋转操作来编码位置信息，编码的是相对位置而非绝对位置。当前所有主流模型（Llama/DeepSeek/Qwen）使用。
- **解决什么问题**：支持更好的相对位置感知、更长的上下文外推能力（训练 4K 推理 128K 也能用）。
- ✅ **已学**

### KV Cache
- **是什么**：在生成过程中缓存已有 token 的 K 和 V 矩阵，避免重复计算。
- **解决什么问题**：Autoregressive Decoding 每生成一个 token 都要重新算之前所有 token 的 Attention——KV Cache 让这一步从 O(n²) 降到 O(n)。代价是用显存换速度。
- ✅ **已学**

### FlashAttention
- **是什么**：通过分块（tiling）把 Q/K/V 加载到 SRAM 中一次算完 Attention，不反复读写 HBM。
- **解决什么问题**：标准 Attention 的瓶颈不是计算，是 HBM←→SRAM 间的数据搬运——FlashAttention 把 HBM 读写从 O(N²) 降到 O(N)，加速 2-4 倍。
- ✅ **已学**

### PagedAttention
- **是什么**：把 KV Cache 按"页"管理，类似操作系统虚拟内存分页。
- **解决什么问题**：KV Cache 占显存大头且碎片化——PagedAttention 让显存利用率从 20-40% 提升到 95%+。vLLM 框架的核心创新。
- ✅ **已学**

### Speculative Decoding（推测解码）
- **是什么**：用小模型快速"草稿"生成多个 token，大模型一次验证这些 token 的正确性。
- **解决什么问题**：大模型生成慢——Speculative Decoding 让生成速度提升 2-3 倍，输出质量不变。
- 🔶 **部分掌握**（含在推理优化笔记中）

### Context Window（上下文窗口）
- **是什么**：模型一次能"看到"的最大 token 数（GPT-4: 128K, Claude: 200K, Gemini: 1M）。
- **解决什么问题**：窗口越大，模型能处理的内容越多——长文档分析、长对话、代码仓库理解。
- ⬜ **待学**

### Scaling Law（规模缩放定律）
- **是什么**：模型性能随参数、数据、算力同步增长可预测地提升。2020 年 OpenAI 发现，2024 年起进入收益递减区。
- **解决什么问题**：指导资源分配——知道堆参数的性价比。当 Scaling Law 撞墙后，MoE 成为主流应对方案。
- ✅ **已学**

### Dense 模型（稠密模型）
- **是什么**：推理时所有参数全部激活的传统模型（GPT / Llama / Claude）。和 MoE 相对。
- **解决什么问题**：结构简单、训练稳定。但参数全激活，成本随参数线性增长，在 Scaling Law 撞墙后走向 MoE。
- ✅ **已学**

### In-context Learning（上下文学习, ICL）
- **是什么**：不给模型微调，只在 Prompt 中给几个例子（Few-shot），模型就能"学会"执行新任务。
- **解决什么问题**：不需要训练数据、不需要改模型——零成本让模型适配新任务。
- ⬜ **待学**

### Few-shot / Zero-shot（少样本/零样本学习）
- **是什么**：Few-shot = 给几个例子引导模型；Zero-shot = 不给例子，只靠指令让模型完成新任务。
- **解决什么问题**：降低模型使用门槛——不需要为每个新任务准备训练数据。
- ⬜ **待学**

### Knowledge Distillation（知识蒸馏）
- **是什么**：让大模型（教师）生成软标签，小模型（学生）学习教师模型的输出分布，继承大模型的能力。
- **解决什么问题**：把大模型的能力"压缩"进小模型——Phi-3 只有 3.8B 参数，性能接近 7B 模型。
- ⬜ **待学**

## 06 - 安全与对齐

### Hallucination（幻觉）
- **是什么**：模型生成看似合理但实际错误的内容——不是"说错"，是"自信地编造"。
- **解决什么问题**：这是语言模型工作机制的必然结果（预测下一个 token），不是 bug。缓解手段包括 RAG、低 Temperature。
- ✅ **已学**

### AI Safety（AI 安全）
- **是什么**：确保 AI 系统的行为可预测、可控、不产生意外危害的学科。
- **解决什么问题**：能力越强、越需要边界——防止模型被恶意利用、产生偏见、泄露隐私。
- ⬜ **待学**

### Alignment（对齐）
- **是什么**：让 AI 的目标与人类的价值观和期望一致的技术。RLHF 是主要的对齐方法之一。
- **解决什么问题**：模型可能有强大的能力但行为不当（撒谎、偏见、有害）——对齐确保模型"做好事"。
- ⬜ **待学**

### Jailbreak（越狱）
- **是什么**：通过精心构造的提示词绕过模型的安全限制，让模型输出本应被禁止的内容。
- **解决什么问题**：理解越狱攻击方式才能防范——这是安全对齐的红队测试手段。
- ⬜ **待学**

### LLM 评估体系
- **是什么**：评估 LLM 输出的三种方式：词汇匹配（ROUGE/BLEU）→ LLM-as-Judge → 生产可观测性。
- **解决什么问题**：模型输出没有"标准答案"——需要系统化的评估框架来衡量质量。
- 🔶 **部分掌握**（有笔记内容）

### 红队测试（Red Teaming）
- **是什么**：主动找漏洞的安全测试方法——让一队人去"攻击"模型，找出安全弱点。
- **解决什么问题**：被动防御永远有遗漏——主动攻击才能发现意想不到的漏洞。
- ⬜ **待学**

### Constitutional AI
- **是什么**：Claude 用的对齐方法——给模型一套"宪法"规则，让模型自我修正，减少对人类反馈的依赖。
- **解决什么问题**：RLHF 需要大量人工标注——Constitutional AI 让模型自己判断是否符合规则，降低对齐成本。
- ⬜ **待学**

## 07 - 对比与前沿

### 符号主义 / 专家系统
- **是什么**：AI 第一波浪潮。知识 = 人类写的 if-then 规则，推理引擎做规则匹配。
- **解决什么问题**：优点是完全透明可解释。缺点是规则写不完（常识地狱），1990 年代被统计方法取代。
- ✅ **已学**

### 连接主义 / 神经网络
- **是什么**：AI 第二波浪潮（当前主流）。知识 = 从海量数据中自动学到的权重分布。
- **解决什么问题**：解决了专家系统的"知识获取瓶颈"——不需要人写规则，数据驱动自动学习。
- ✅ **已学**

### 行为主义 / 强化学习
- **是什么**：AI 第三学派。知识 = 从环境交互中试错积累的策略。
- **解决什么问题**：解决了"没有标准答案只有好坏评分"场景下的学习问题——AlphaGo、RLHF 都属于这个范式。
- ✅ **已学**

### 小语言模型（SLM, Small Language Model）
- **是什么**：参数规模 1B-8B 的模型（Phi-3, Gemma, TinyLlama），通过高质量数据 + 知识蒸馏做到比大模型参数少但能力接近。
- **解决什么问题**：端侧部署、低延迟、隐私保护、低成本的场景不需要大模型的极致通用能力。
- ✅ **已学**

### 推理模型（o1 / R1 / 思维链推理）
- **是什么**：在推理时生成内部思维链，花更多时间"思考"后再给出答案的模型（OpenAI o1, DeepSeek-R1）。
- **解决什么问题**：传统 LLM 在复杂推理任务上不够好——推理模型通过 test-time compute 换取更准确的答案。
- ⬜ **待学**

### 多模态（Multi-modal）
- **是什么**：一个模型同时处理文字、图片、音频、视频等多种输入形式（GPT-4V, Gemini）。
- **解决什么问题**：人类通过多种感官理解世界——单模态模型只"读了文字"，多模态模型能"看到、听到、读懂"。
- ⬜ **待学**
