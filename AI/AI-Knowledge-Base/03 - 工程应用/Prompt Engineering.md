# 提示词工程与思维链（Prompt Engineering + CoT）

> ✅ 已学习 — 2026-05-18
>
> 写提示词不是在"和模型说话"——是在**给模型画靶心**。
> 靶心画得越清楚，模型射中的概率越高。

---

## 一句话本质

**提示词工程 = 缩小模型的"猜测范围"，从 100K 词表缩小到几十个候选。**

模型每一步都在预测下一个 token——提示词越模糊，它需要猜测的空间越大，出错的概率越高。

---

## 五要素框架

任何提示词，不管长短，都在组合这五样东西：

| 要素 | 作用 | 例子 |
|---|---|---|
| **① 角色** | 限定模型的回答角度 | "你是一个资深 Python 工程师" |
| **② 任务** | 明确告诉模型要做什么 | "把这段代码重构为异步版本" |
| **③ 上下文** | 给模型足够的信息背景 | "这是用户的生产环境代码" |
| **④ 格式** | 规定输出的结构 | "用 JSON 格式输出" |
| **⑤ 约束** | 设定边界和限制 | "不超过 200 字，不要用专业术语" |

### 优先级：角色 + 约束 > 任务 + 上下文 + 格式

如果没时间写全五个，**优先保证角色和约束**：

```
角色：单设角色就能把回答质量提升一个档次
  "你是一个资深 Python 工程师" → 代码质量明显高于不设角色

约束：告诉模型"不要做什么"比"要做什么"更管用
  "不要使用专业术语" → 比"用简单的话说"更精确
  "不要输出 Markdown" → 比"用纯文本"更直接
```

### 对比

```
❌ 模糊： "帮我写点东西"
  模型要猜：角色？任务？格式？长度？风格？→ 质量不稳定

✅ 清晰： "你是一个资深客服经理（角色），
           帮我写一封道歉邮件（任务），
           发给因物流延迟而投诉的客户（上下文），
           用纯文本格式（格式），
           200 字以内，语气真诚（约束）"
  模型不用猜任何事 → 输出质量稳定
```

## Chain of Thought（思维链）

### 是什么

在提示词里要求模型**把推理过程显式写出来**，而不是直接给答案。

```
没有 CoT：
  问：200 × 0.7 - 30 = ?
  答：110 ← 蒙对的还是算对的？不知道

有 CoT：
  问：200 × 0.7 - 30 = ? 请一步步思考
  答：200 × 0.7 = 140 → 140 - 30 = 110
      ↑ 每一步都看得见，错了也知道错在哪步
```

### 为什么有效

不是模型推理能力变强了——是把 latent space 里的"隐含推理链"显式化成了 token：

```
没有 CoT：
  模型在 latent space 里试图"一步跳到答案"
  → 步骤越多，跳歪概率越大

有 CoT：
  模型每输出一个 step token，就把它拼回输入
  → 下一步的推理基于上一步的显式结果
  → 错误不会跨步传播
```

### 三种用法

| 类型 | 做法 | 场景 |
|---|---|---|
| **零样本 CoT** | 问题末尾加"请一步步思考" | 日常最常用，加四个字即可 |
| **少样本 CoT** | 给一个完整的例子（含思考过程） | 需要特定推理格式时 |
| **结构化 CoT** | 规定思考过程的输出格式 | 需要程序化解析推理过程时 |

**零样本 CoT 是最划算的提示词技巧**——加四个字"一步步思考"，推理准确率可提升 20-50%。

## Few-shot（少样本）

### 是什么

在提示词里给 2-3 个例子，让模型学会你要的输出模式。

### 什么时候用

需要的输出格式非常固定，但用文字描述不清楚：

```
❌ 只用文字描述：
  "请从邮件中提取发件人、主题、日期，用 JSON 输出"
  → 模型可能输出 3 种不同的格式，不稳定

✅ 给例子：
  邮件：你好，我是李四，关于明天的项目会议…
  输出：{"sender": "李四", "subject": "项目会议"}

  邮件：王五发来合同终稿，请查收
  输出：
  → 模型看到规律了 → 自动按同一格式输出
```

### 三个关键

```
① 例子放在最前面（先让模型看到模式，再给真实问题）
② 例子给 2-3 个就够了（不是越多越好）
③ 例子的质量比数量重要（一个完美例子 > 三个模糊例子）
```

---

## CoT + Few-shot 组合（最强提示词技巧）

```
问题：2 + 3 = ?
思考：2 + 3 = 5
答案：5

问题：5 + 7 = ?
思考：5 + 7 = 12
答案：12

问题：一件衣服原价 200 元，打 7 折后再减 30 元，最后多少钱？
思考：
```
→ 模型自动输出：200 × 0.7 = 140 → 140 - 30 = 110 → 答案：110

**给例子（Few-shot）+ 要求一步步思考（CoT）= 几乎所有推理任务上的最佳实践。**

## 常见陷阱

| 陷阱        | 表现              | 解法           |
| --------- | --------------- | ------------ |
| **过度约束**  | 约束太多模型反而"僵住"    | 核心约束 2-3 条足够 |
| **角色冲突**  | 既说"你是专家"又说"简单点" | 角色和行为一致      |
| **例子太少**  | 模型没学到模式         | 至少给 2 个例子    |
| **例子质量差** | 模型学到错误模式        | 检查例子的正确性     |
| **提示词过长** | 关键信息被稀释         | 最重要的放最前面或最后面 |

## 🧪 摸底自测

#### Q1（入门）
> 提示词五要素是哪五个？如果没时间写全，优先保证哪两个？

<details>
<summary>解答</summary>

角色、任务、上下文、格式、约束。优先保证角色（限定回答角度）和约束（告诉模型不要做什么）。
</details>

#### Q2（进阶）
> CoT 为什么有效？它在 latent space 层面做了什么？

<details>
<summary>解答</summary>

CoT 把隐含推理链从 latent space 显式化为 token。没有 CoT 时模型试图一步跳到答案（步骤越多越容易歪），有 CoT 时每步结果是显式的、可验证的、不会跨步传播错误。
</details>

#### Q3（提升）
> CoT + Few-shot 组合为什么是最强提示词技巧？什么场景下用这个组合？

<details>
<summary>解答</summary>

Few-shot 让模型看到输出模式（格式），CoT 让模型看到推理过程（路径）。组合起来模型既知道"输出长什么样"，也知道"怎么走到那个输出"。适合复杂推理、数学、多步骤任务。
</details>
